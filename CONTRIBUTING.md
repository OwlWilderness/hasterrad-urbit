# Contributing

Use an existing relevant GitHub issue, or create and verify a concise issue before committing authorized work. Every commit must contain `Refs #N` with a real related issue number. Do not use automatic closing keywords while release acceptance remains outstanding.

Use `<type>/<issue-number>-<short-description>` branches (`feat`, `fix`, `docs`, `chore`). Keep unrelated active writers in separate worktrees, stage only reviewed exact paths, and verify committed blobs. Do not blanket-stage historical untracked trees.

Run the README's portable checks against a clean snapshot. Native behavior, saved-world migration, clean desk admission and actual frontend distribution require their own compatible disposable-runtime/owner-controlled release qualification; static sentinels are not substitutes. Keep source changes and `source-manifest.json` consistent.

Never commit pier keys, login codes, certificates/private keys, private hosts, personal paths, operational handoffs, receipts or mutable worker evidence. Preserve dependency notices. Do not overwrite a live Docket descriptor with the fresh-install template. Commits do not authorize pushing, changing visibility, installing, restarting, closing issues or publishing a glob.
